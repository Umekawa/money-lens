# ブラウザUI監査

画面を実際に操作して、コードだけでは分からない使いにくさをIssue候補にまとめるための手順です。個人データを扱わずに再現できるよう、監査では必ず匿名デモを使います。

## 実行手順

1. リポジトリのルートでローカルサーバーを起動する。

   ```powershell
   python -m http.server 8765
   ```

2. `http://127.0.0.1:8765/?demo=1` をブラウザで開く。`?demo=1` がないURLや実データのCSVは監査に使わない。
3. 次の導線を上から順に操作し、各項目の期待結果と実結果を記録する。
4. 失敗があれば、下のテンプレートをコピーしてIssue候補を作る。GitHubへのIssue作成は、明示的に許可された場合だけ行う。

## 操作チェック表

| 導線 | 操作 | 期待結果 |
| --- | --- | --- |
| 起動 | ページを開く | デモバッジと匿名デモ案内が表示され、空状態のままにならない |
| CSV読み込み | 「データをクリア」後に「匿名のデモデータを見る」を押す | ダッシュボード、収支、資産推移、明細が表示される |
| 検索 | 明細検索に `給与`、次に存在しない文字列を入力する | 前者は該当明細、後者は「該当する明細がありません」と表示される |
| 月選択 | 月選択を `2026-01` と `2026-02` に切り替える | カテゴリ別支出と明細が選択月に切り替わる |
| 資産クリック | 資産推移の棒をクリックする | 対応する月が選択され、明細欄へスクロールする |
| キーボード | 資産の棒にTabで移動し、EnterまたはSpaceを押す | クリックと同じ月選択が行われる |

### 判定

- **Pass**: 期待結果と実結果が一致する。
- **Issue候補**: 操作が完了しない、表示が矛盾する、または次の操作が分からない。
- ブラウザの幅を変えて再現性も確認する。少なくとも通常幅とスマートフォン相当幅で確認する。

## Issue候補テンプレート

```markdown
## 概要

<!-- 何が使いにくいかを1文で書く -->

## 再現手順

1. `http://127.0.0.1:8765/?demo=1` を開く
2. <!-- 操作を具体的に書く -->

## 期待結果

<!-- 本来どうなるべきか -->

## 実結果

<!-- 実際にどうなったか。個人データは書かない -->

## 環境

- ブラウザ:
- 画面幅:
- 再現率:
```

監査結果に個人CSVのファイル名、金額、口座名、URLのクエリ値を含めないこと。Issue作成前に匿名デモURLと上記項目だけになっているか確認する。
