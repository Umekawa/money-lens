# money-lens

マネーフォワードのCSVをブラウザ内で分析する個人用ダッシュボードです。

## 対応CSVと集計ルール

### 対応するCSV

CSVは「CSVを選択」から個別に、または「フォルダを選択」から複数選択できます。HTTPサーバーで使う場合は、`csv-manifest.json` に `csvs/` 配下の相対パスを列挙すると自動で読み込めます。公開用の匿名サンプルは `samples/transactions.csv` と `samples/assets.csv` です。

| 種類 | 必須列 | 任意列・判定 |
| --- | --- | --- |
| 明細 | `日付`、`金額` | `内容` または `摘要`、`大項目` または `カテゴリ`、`計算対象` |
| 資産 | `日付`、`合計`・`総額`・`純資産`・`総資産`・`残高合計` のいずれか1列 | 日付と合計列以外は資産内訳として表示 |

ヘッダーの空白は無視し、資産の合計列は `合計（円）` のような単位付き表記にも対応します。日付は `YYYY-M-D` または `YYYY/M/D`（区切りは混在不可）の実在する日付、金額は符号・3桁区切り・`円`/`¥`/`￥`付きの数値を使用してください。文字コードは UTF-8 または Shift_JIS に対応します。必須列がない行や、日付・金額・資産内訳が不正な行は取り込まず、ファイル名と行番号を画面に表示します。CSV以外のファイルはスキップします。

### 取込・保持のルール

1. 読み込んだデータはサーバーへ送信せず、現在のページを開いている間だけブラウザのメモリ上に保持します。ページの更新・タブを閉じる操作で消えるため、保存機能や永続化機能はありません。
2. 「デモデータを表示」とユーザーCSVは混在せず、データセットを切り替えると前のデータは破棄されます。「データをクリア」では読み込み済みの明細・資産・取込結果を消去します。
3. `ID`・`明細ID`・`取引ID`列がある明細はIDで照合し、異なるIDの明細は内容が同じでも保持します。同じIDの明細を再度読み込んだ場合は後から読み込んだ内容で更新します。IDがない明細は日付・内容・カテゴリ・金額で照合し、同じキーは期間重複や別名CSVの再取込として除外します。同じキーの行が実際には別明細でもIDなしでは識別できないため、利用者はCSVに安定したID列を含めることで正当な重複を保護できます。同一ファイル内にある同一内容の複数行は個数分保持します。
4. 資産は同じ日付のデータを後から読み込んだ値で置き換えます。資産グラフは24件以下なら記録単位、24件を超えると各月の最新値に集約して最大24か月ずつ表示します。「古い期間」「新しい期間」で過去の履歴にも移動できます。データがない月は補完しないため、24か月は記録がある月の数です。表示中の日付範囲・件数はグラフ上の「表示期間」で確認でき、「最新」は全資産データの最新記録を示します。
5. `計算対象` 列がある明細は、値が `1` の行だけを集計・表示します。列がない場合はすべての行を対象にします。

   安定したID列があるCSVで同じIDを `1` から `0` に訂正して再取込すると、そのIDの明細は集計・一覧から除外され、取込結果の除外件数に反映されます。同じIDを後のCSVで再び `1` にすると復帰します。対象外行にIDがない場合は既存明細と照合できず、以前取り込んだ明細は残ります。CSVに存在しない行は削除しません。

### 集計のルール

- 正の金額は収入、負の金額は支出として扱います。収入カードは正の明細合計、支出カードは負の明細の絶対値合計、収支は収入から支出を引いた値です。0円の明細はどちらにも加算しません。
- 振替専用の判定は行っていません。CSVに振替列があっても参照しないため、金額の符号だけで集計されます。正の返金・払い戻しは収入として扱われます。
- カテゴリ別支出は負の明細だけを対象にし、カテゴリが空なら「未分類」にします。上位8カテゴリ以外は「その他」にまとめます。
- 「カテゴリ別支出」の月選択は、収入・支出・収支・表示期間・カテゴリ・月別グラフと金額表・明細に適用されます。「全期間」に戻すと月の絞り込みを解除します。資産グラフには月フィルターを適用しません。明細の検索は明細一覧だけを絞り込み、集計やグラフは変えません。
- 月別グラフは初期表示で最新の最大24か月を古い月から並べます。「古い期間」「新しい期間」は資産と月別グラフで共通の履歴位置を移動します。それぞれ記録がある月を最新側から24か月単位で区切るため、両グラフの日付範囲は一致しない場合があります。月選択を変更すると月別グラフの履歴位置は初期化されます。
- 資産グラフの合計は資産CSVの合計列を使用し、棒を選ぶと日付ごとの内訳を確認できます。「この月の明細へ」は該当月の明細がある場合に月フィルターを設定し、明細一覧へ移動します。

### 対応ブラウザ・確認範囲と制限

File APIとTextDecoderを利用できる最新版のChrome/Edge/Firefox/Safariを対応対象とします。確認済み範囲はPlaywright Chromiumによる合成CSVの自動監査と、幅1280/820/390/320pxの画面確認です。これは各ブラウザ実機での動作保証ではありません。Firefox/Safari実機と公開URLでの最終確認は [Issue #266](https://github.com/Umekawa/money-lens/issues/266) で追跡しています。

リリース前の手動確認では「CSVを追加」から合成CSVを選択し、集計・検索・月選択・301件以上のページ送り・再取込・「読み込みを中止」・「データをクリア」、および390px幅で資産内訳と長い金額表示を確認してください。Safariの0円資産棒の操作も対象です。常時チェックはChromiumのみです。

大量データの対応件数・ファイル数・応答時間・メモリの保証範囲は未確定で、[Issue #269](https://github.com/Umekawa/money-lens/issues/269) で決定します。合成データの探索的測定では、3万明細を300ファイルに分けた取込で約40秒、30万明細の連続検索で約10秒、同内容の別名CSVの反復取込で保持メモリ増加が確認されています。「読み込みを中止」はファイル間で受け付けますが、単一ファイルの解析中は操作が遅れ、完了まで中止できない場合があります。測定完走や過去の性能予算案は対応規模の保証ではありません。測定方法と既知の制限は [大量データ調査](docs/scale-audit-2026-09-23.md) および #269 を参照してください。

## 開発

個人CSVは `csvs/` に置けますが、Gitには登録されません。

下記のPythonサーバーでは、`csvs/` にCSVを置くだけでサブフォルダも含めて自動探索します。読み込み対象を指定したい場合やディレクトリ一覧を提供しないサーバーでは、公開可能な雛形 `csv-manifest.example.json` を `csv-manifest.json` にコピーし、実際のCSVに合わせて編集してください。`csv-manifest.json` は個人のファイル名が含まれる可能性があるためGitの登録対象外です。マニフェストがある場合はその指定を優先し、404の場合だけフォルダ一覧に切り替えます。取得や探索に失敗した場合は画面に案内します。

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

ブラウザで <http://localhost:8765> を開きます。

`index.html` を直接開く場合（`file:///…`）は、ブラウザの制限により `csvs/` を自動取得できません。画面の「CSVフォルダを読み込む」からフォルダを選択するか、「CSVを追加」からファイルを選択してください。手動選択はサーバー不要です。

ローカルチェック：

Node.jsとnpmを用意し、`npm ci` で開発依存を導入してください。標準チェックにPowerShellやローカル専用の自動開発ツールは不要です。

```powershell
npm run check
```

個人データを使わずにUI監査を実行する場合は、Playwright用Chromiumを準備して次を実行します。監査サーバーは空きポートでループバックにのみ起動し、`index.html`・`styles.css`・`app.js` だけを配信します。

```powershell
npx playwright install chromium
npm run ui:audit
```

結果とスクリーンショットは `artifacts/ui-audit/` に保存されます。

大量データ時の調査を再実行する場合は、Chromiumを準備して次を実行します。合成CSVだけを使い、取込・検索・中止・保持メモリを測定します。

```powershell
npx playwright install chromium
npm run perf:audit
```

測定条件と結果の解釈は [大量データ調査](docs/scale-audit-2026-09-23.md) を参照してください。結果は `artifacts/scale-audit/` に保存します。

## 開発方針

管理者用の自動開発ツールはGit除外の `.local-dev/` にローカル保管し、公開リポジトリ・CIには含めません。アプリの開発・チェックにこれらのツールは不要です。

調査記録: [2026-09-23のプロダクト課題](docs/product-audit-2026-09-23.md)。

`docs/` には公開可能な仕様・調査記録を保存してGitで管理します。個人情報や未公開メモは含めず、ローカルだけで残す調査素材はgitignore対象の `artifacts/` に保存してください。gitignoreは登録済みファイルや過去の履歴、公開済みIssueを非公開にはしません。

### 基本方針

- GitHub Issuesを課題管理に使う
- 個人データ・CSVは公開しない
- 変更前後にローカルチェックを実行する
- GitHub ActionsはチェックとGitHub Pagesデプロイの最小構成にする

## 公開デモ

GitHub Pages用のワークフローは `main` ブランチへの更新時にデプロイを実行します。公開用成果物はCSVフォルダの自動探索を行わず、匿名のデモデータを表示します。

**2026-09-24時点では公開成功を未確認です。** Pages APIは404を返しており、設定復旧は [Issue #265](https://github.com/Umekawa/money-lens/issues/265) で追跡しています。標準の公開先候補は <https://umekawa.github.io/money-lens/> ですが、利用可能な公開URLとしては未確定です。管理者が **Settings → Pages → Source: GitHub Actions** と利用条件・権限を確認し、デプロイ成功後に実際のURLと公開SHAを確認して、この案内を更新します。

### 初回利用（匿名デモ → 合成CSV → クリア）

公開後は上記で確認したURLを開きます。公開前に試す場合は `index.html` を直接開き、空の画面の「匿名のデモデータを見る」、または上部の「デモデータを表示」を押してください。

1. 「デモモード」と匿名サンプルの案内を確認します。収入560,000円・支出142,000円・収支418,000円、最新資産1,925,000円が表示されます。
2. リポジトリの合成CSV [明細サンプル](samples/transactions.csv) と [資産サンプル](samples/assets.csv) をダウンロードします。GitHubではファイル画面の「Download raw file」を使い、HTMLページではなくCSVを保存してください。Pagesの配信対象はアプリの3ファイルのみで、これらのサンプルは含みません。
3. 上部の「CSVを追加」から保存した2ファイルを選択します。デモ表示が解除され、合成CSVに切り替わります。取込結果と集計、月選択、明細検索、資産棒の内訳を確認してください。フォルダ単位なら「CSVフォルダを読み込む」を使えます。空の画面では「CSVを選択」「フォルダを選択」も利用できます。
4. 「データをクリア」を押し、確認ダイアログで消去します。明細・資産・取込結果が消えて空の画面に戻ります。元のCSVファイルは削除されません。「デモデータを表示」で匿名デモを再表示できます。

ユーザーCSVはメモリ上だけに保持され、再読み込みで消えます。公開デモでは再読み込み後に匿名デモが再表示されます。Pages公開と正式リリースは別であり、タグ・GitHub Releaseの作成を伴う正式リリース時には [リリース手順](docs/release.md) に従い、CHANGELOGのUnreleasedを対象バージョンへ整理します。
